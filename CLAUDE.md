# sync-payments — правила работы с репозиторием

Приложение Bitrix24 «Распределение оплат»: помогает распределять пришедшие
платежи (смарт-процесс «Оплаты») по связанным сделкам.

## Язык

Общаемся и пишем документацию на русском.

## Тип приложения

- **LOCAL** — одно-портальный режим (без OAuth-маркетплейса и multi-tenant).
- Встраивается во вкладку карточки смарт-процесса «Оплаты» через `placement.bind`
  (см. `app/pages/install.html.client.vue`).
- SPA: `ssr: false`, статическая генерация (`nuxt generate` → `.output/public`).

## Стек (целевой стандарт флота aidapioneer)

| Слой              | Технология                                                                      |
| ----------------- | ------------------------------------------------------------------------------- |
| Пакетный менеджер | pnpm (поле `packageManager`), Node 22+                                          |
| Фреймворк         | Nuxt 4 (Nitro + Vue 3)                                                          |
| Стили             | Tailwind 4 (`@import "tailwindcss"`) + тема `@bitrix24/b24ui-nuxt`              |
| UI-кит            | `@bitrix24/b24ui-nuxt` + `@bitrix24/b24icons-vue` (**только официальные**)      |
| Bitrix24 SDK      | `@bitrix24/b24jssdk` + `@bitrix24/b24jssdk-nuxt` (плагин `$initializeB24Frame`) |
| Линт/типы         | ESLint flat (`@nuxt/eslint`) + `nuxt typecheck` (vue-tsc, strict)               |

**Запрещено:** форки `@bxshefby/*`, самодельные копии готовых b24-компонентов,
прямые REST-запросы. Любой вызов REST — только через SDK (`$b24.callBatch`,
`fetchListMethod`, `callBatchByChunk` и т.п.).

## Ветки и пуши

- **В `main` напрямую не пушим.** Вся работа — в отдельной ветке через Pull Request.
- В один PR — одна логическая задача. Описание PR на русском: что, зачем, на что влияет.
- Мержит владелец репозитория. Автомерж и принудительный мерж не используем.

## Definition of Done

Перед коммитом/PR прогоняем **`./verify.sh`** (linux/macOS) или **`verify.ps1`**
(Windows). Должно быть зелёным:

```
pnpm install --frozen-lockfile   # детерминированная установка
pnpm format:check                # prettier (стиль)
pnpm lint                        # eslint
pnpm typecheck                   # nuxt typecheck (vue-tsc, strict)
pnpm test                        # vitest
pnpm generate                    # production-сборка не сломана
```

CI повторяет эти же проверки. PR не мержится без зелёного CI.

## Конфигурация портала

Магические идентификаторы портала (id смарт-процессов, категорий, статусов)
держим в `runtimeConfig.public` (`nuxt.config.ts`), а не разбросанными по коду.
Их можно переопределять переменными окружения `NUXT_PUBLIC_*` при сборке.

## Секреты

Только в env/secrets. Никогда — в код, логи или коммиты. Данные портала и
реквизиты не логируем в проде и не публикуем на скриншотах.
